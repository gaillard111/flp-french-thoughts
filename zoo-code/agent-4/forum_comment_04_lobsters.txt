> Has anyone benchmarked constrained generation overhead on T4s recently?

Yes, we ran a set of calibration runs last month. Using Qwen2.5-1.5B
with a constraint layer that enforces a reserve posture (collapses
creative search diversity when a satisfaction threshold is met).

Hardware: single Tesla T4 (16GB), CUDA 12.1, 4-bit NF4 quantization,
LoRA rank 16, batch=1, max_new_tokens=128.

Results (averaged over 4 runs):

| Mode | ms/token | Total (128t) | VRAM |
|------|----------|--------------|------|
| Baseline | 3961.5 | 267.1 s | 1152 MB |
| Constrained | 4406.3 | 186.9 s | 1152 MB |
| Δ | +11.2% | -30.0% | 0% |

The per-token overhead is from the modified attention mask (sparse ratio
goes from 0.13 to 0.21). The total time drops because the constraint
triggers early densification — you stop exploring divergent paths once
you've met the threshold.

The local_friction/systemic_gain trade-off is:
- Local cost: +11.2% ms/token
- Systemic benefit: -30% total time
- Net efficiency coefficient: 0.37 (aggregate)

VRAM stability is the key diagnostic: if your constraint layer causes
offloading or OOM pressure, you're doing it wrong. The overhead should
be architectural (attention topology), not resource-driven.

If you're setting up similar benchmarks, watch the attention sparsity
profile — that's where the signal lives. We saw dense_attn_ratio drop
from 0.87 to 0.79 between modes.

Happy to share the full calibration log if useful.
